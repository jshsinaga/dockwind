# Dockwind Release

Status: active. This document owns versioning, local packaging, and hosted CI.
Read `docs/HANDOFF.md` for current evidence and `docs/CONFIGURATION.md` for the
runtime configuration contract.

Last updated: 2026-11-11

## 1. Versioning

The version has one source: `version` in `Cargo.toml`.

- Use `MAJOR.MINOR.PATCH`, for example `0.2.0`.
- The Windows manifest version is generated by `build.rs` from the package
  version and is not edited by hand.
- A release tag is `v` followed by the exact package version, for example
  `v0.2.0`.
- The release workflow rejects a tag that does not match `Cargo.toml`.

Update the version and refresh `Cargo.lock`:

```powershell
.\scripts\bump-version.ps1 0.2.0
```

Commit `Cargo.toml` and `Cargo.lock`, then create the tag:

```powershell
git tag v0.2.0
git push origin v0.2.0
```

Do not move or reuse a published tag.

## 2. Local Installer

Requirements:

- Rust toolchain from `rust-toolchain.toml`.
- Inno Setup 6. Install it with `choco install innosetup -y` or from
  <https://jrsoftware.org/isinfo.php>.
- The release binary is built by the script.

```powershell
.\scripts\build-installer.ps1
```

The version defaults to `Cargo.toml`. Override it only for a manual test:

```powershell
.\scripts\build-installer.ps1 -Version 0.2.0
```

Output:

```text
dist\Dockwind-<version>-setup.exe
```

On 2026-11-11, Inno Setup 6.7.3 built the final
`dist\Dockwind-0.2.0-setup.exe`. A silent 0.1.0 install, a 0.2.0 upgrade over it,
a settings-window launch, and an uninstall passed on this development profile.
The installed settings title read `Dockwind Settings 0.2.0`. The Start Menu
shortcut existed after install. Uninstall removed the install directory and
shortcut and preserved the config. A clean Windows profile is still untested.

The installer is unsigned. Windows SmartScreen may warn on first run. Code
signing is future work and needs a certificate and a signing decision.

## 3. Installer Behavior

| Item | Behavior |
|---|---|
| Scope | Per-user. No administrator prompt |
| Default path | `{autopf}\Dockwind`, which is a per-user program path for a lowest-privilege install |
| Shortcuts | Start Menu always, desktop shortcut optional |
| Autostart | Not forced. Enable it from the tray or the settings window |
| Upgrade | The same AppId and path are reused. Existing config and logs are kept |
| Uninstall | Runs `--disable-autostart` and `--restore-taskbar` before removing files |
| User data | `%APPDATA%\Dockwind\config.toml` and logs are preserved by default |

The installer does not delete the user's config. Remove it manually only when a
clean reset is intended.

## 4. Hosted CI

`.github/workflows/ci.yml` runs on every push to `main`, every pull request, and
manual dispatch. The gate job runs `scripts/check.ps1` on `windows-latest` with
the pinned toolchain and Rust cache. On non-pull-request runs, an `installer` job
depends on the gate, installs Inno Setup, builds the installer, and uploads it as
the `Dockwind-installer` workflow artifact.

`.github/workflows/release.yml` runs on a `v*` tag or manual dispatch with an
existing tag. It:

1. Checks the tag against `Cargo.toml`.
2. Builds the release binary with locked dependencies.
3. Installs Inno Setup.
4. Builds the installer.
5. Uploads the installer artifact.
6. Creates or updates a GitHub Release with the installer and generated notes.

The workflow uses the repository `GITHUB_TOKEN` with `contents: write`. No extra
secret is required for an unsigned build.

## 5. Release Checklist

1. The working tree is clean.
2. `.\scripts\check.ps1` passes.
3. The version in `Cargo.toml` is updated and `Cargo.lock` is committed.
4. The config schema and runtime behavior match `docs/CONFIGURATION.md`.
5. `docs/HANDOFF.md` lists manual checks and dated evidence.
6. The tag matches the version and is pushed.
7. The release workflow produces `Dockwind-<version>-setup.exe`.
8. Download the artifact and run a smoke test on a clean Windows profile.

The taskbar-hiding checks in `docs/HANDOFF.md` still apply before a release is
called verified.

## 6. Manual Recovery

If an installer or a test leaves the taskbar hidden, run the installed or built
binary with:

```powershell
dockwind --restore-taskbar
```

This command runs before the single-instance check and does not need a running
dock.
